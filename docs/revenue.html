For BI reviewers: how this page is built

All figures on this page are produced by a Python and SQL pipeline in this repository and exported as JSON. Nothing is typed in by hand.

  • Data: about 640,000 sample bookings and 78,000 denied requests generated by generate.py. Requests are replayed against room inventory in booking order, so sell-outs, denials and cancellations behave as they do in a real reservation system.
  • Warehouse: SQLite star schema built by SQL scripts: dimensions for hotel, date, segment and channel; facts at booking, stay-night and denied-night grain; a daily hotel mart. Ten data quality checks must pass before the site data refreshes.
  • Pace: on-the-books at any lead time is rebuilt from booking and cancellation dates on the stay-night fact, which is equivalent to keeping a nightly reservation snapshot.
  • Forecast: additive pickup by hotel, weekday and month, back-tested on the last 12 months against a same-day-last-year (364-day) baseline.
  • Unconstraining: for each sold-out night, the last lead time at which it was under 90% full is found; similar nights that came close to selling out but stayed open supply the expected pickup ratio from that point. The sample's known denials are used only to measure accuracy, never in the estimate.
  • Demand levels: expected unconstrained demand divided by capacity: 100% and above is Compression, 85% High, 60% Shoulder, below 60% Need.
  • Code: demand.py, site_export.py, build.py.
